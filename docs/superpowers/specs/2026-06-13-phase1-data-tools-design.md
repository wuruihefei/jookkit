# 设计:阶段一前端三件(SQL 历史 / 结果网格增强 / 导出)

- 日期:2026-06-13
- 状态:已与用户对齐,待实现计划
- 范围:JookKit 前端(C++/Qt),后端基本不改动

## 1. 背景与目标

JookKit 是类 Navicat/DBeaver 的轻量数据库工具(Qt 前端 + Java 后端双进程,
支持 MySQL/MariaDB/SQLite)。当前已具备连接管理、对象树、SQL 编辑器、查询
结果网格、表数据增删改、表结构编辑、MySQL 用户管理、DDL/索引信息窗格。

产品规划确定下一步**补齐日常高频功能**,分两阶段:

- **阶段一(本设计):** SQL 执行历史 + 结果网格增强 + 导出(CSV/JSON/SQL)。
  三者都以前端为主、低风险、见效快,且围绕同一条数据通路(结果网格)彼此关联。
- **阶段二(后续,不在本设计内):** 数据导入(文件解析 + 列映射 + 后端批量写)。

设计参考了主流工具的成熟做法:DBeaver Query Manager(只存 SQL 文本不存结果、
按文本搜索、保留 N 天清理)、各工具的网格内筛选/排序与多格式导出惯例。

## 2. 设计约束(来自现有代码)

- 两个结果网格(`QueryForm::grid_`、`TableDataForm::grid_`)都是 **`QTableWidget`**
  (item-based,不是 model/view 架构)。增强顺着 `QTableWidget` 原生能力做,
  不引入 `QSortFilterProxyModel`、不改网格架构。
- 本地持久化既有模式见 `FavoriteStore`:`namespace` + 配置目录下 JSON 文件
  (与 `connections.json`、`favorites.json` 同目录)。历史沿用同一目录与风格。
- `OptionsDialog` 已存在,可承载历史相关配置项。
- 后端访问统一经 `BackendClient`(前端),是记录 SQL 历史的天然统一拦截点。

## 3. 功能 A:SQL 执行历史

### 3.1 记录内容

只记录 **SQL 文本 + 元数据**,**不存结果集**(结果可能极大;需要时重跑)。
每条记录字段:

| 字段 | 说明 |
|---|---|
| `sql` | 执行的 SQL 文本 |
| `connId` | 连接标识 |
| `db` | 库名(可空) |
| `ts` | 执行时间戳(epoch ms) |
| `elapsedMs` | 耗时(毫秒) |
| `rows` | 影响行数 / 返回行数 |
| `ok` | 成功 true / 失败 false |
| `error` | 失败时的错误信息(成功为空) |

### 3.2 拦截点

在 `BackendClient` 发起「执行 SQL」类请求的统一出口记录一条。元数据类请求
(展开对象树、取 schema、取 DDL 等)**不记录**。判定方式:按 funcId 白名单
(执行 SQL / 增删改 / ALTER 等写操作与查询)纳入,其余排除。

这样 `QueryForm` 的查询、`TableDataForm` 的增删改、表结构编辑的 ALTER 都会
自动入账,无需在每个调用点散布记录代码。

### 3.3 存储

- 文件:配置目录下 `history.jsonl`(JSON Lines,每行一条,**追加写**)。
  追加式避免每次记录都全量重写大 JSON 数组。
- 启动时加载最近 N 条进内存供面板展示。
- **滚动上限**:默认保留**最近 1000 条**或**最近 30 天**(两者取更严者),
  可在 `OptionsDialog` 配置条数与天数。超限时在写入或启动时做一次裁剪
  (重写文件保留尾部 N 条)。
- 失败容错:历史读写出错只记录日志、不阻断主流程(历史是辅助功能)。

### 3.4 UI

- 主窗口新增可停靠「历史」面板(`QDockWidget`),默认隐藏/可由菜单或快捷键切换。
- 面板内容:顶部**搜索框**(即时按 SQL 文本子串过滤)+ 列表(每项显示 SQL 摘要、
  时间、连接/库、成功失败标记、耗时/行数)。
- 交互:
  - 双击一条 → 把 SQL 送回当前 SQL 编辑器(不自动执行)。
  - 右键菜单:复制 SQL / 收藏为常用片段 / 删除此条 / 清空历史。

## 4. 功能 B:结果网格增强

顺着 `QTableWidget` 原生能力做,不改网格架构。

### 4.1 排序

- 开启表头点击排序(`setSortingEnabled(true)`)。
- **仅在只读结果网格(`QueryForm`)启用**。可编辑网格(`TableDataForm`)排序会
  打乱行与主键/原值(`rowOriginals_`/`pkOf`)的对应关系,**保持原序、不启用排序**。

### 4.2 筛选

- 只读结果网格上方新增快速筛选输入框:按关键字子串匹配,不匹配的行用
  `setRowHidden` 隐藏。
- **明确语义**:客户端筛选**只作用于已加载数据**(当前页/当前结果集),不回库
  重查。UI 上以占位提示或副标题说明,避免误以为筛了全表。

### 4.3 复制

- 选中区域 `Ctrl+C` 复制为 **TSV**(可直接粘入 Excel)。
- 右键另提供「复制为 CSV / JSON / INSERT」。

### 4.4 大值查看

- 双击单元格弹出只读查看器(`QDialog` + 文本框),便于查看长文本 / JSON。

## 5. 功能 C:导出

### 5.1 入口与范围

- 入口:只读结果网格工具栏/右键「导出…」。
- 范围选择:**全部 / 仅选中行 / 当前筛选结果**(与 B 的筛选联动:导出可见行)。

### 5.2 格式与选项

| 格式 | 选项 |
|---|---|
| CSV | 分隔符(逗号/制表符/分号)、是否带表头、编码固定 **UTF-8 带 BOM**(便于 Excel 正确识别中文) |
| JSON | 对象数组(列名为 key) |
| SQL INSERT | 指定表名、可批量(多行 VALUES)、标识符按数据源加引号 |

### 5.3 数据来源

- 阶段一**从网格已加载数据导出**(纯前端写文件),通常即当前页/当前结果集。
- 实现走流式写文件(逐行写,不在内存拼大字符串),为后续大数据导出留接口余地。

### 5.4 明确不做(阶段一)

- **整表大数据导出**(后端分页流式拉取):不在阶段一,留作后续增强,避免一上来
  就处理 OOM 与流式复杂度。
- **原生 `.xlsx`**:不做(需引入重依赖;CSV 已可被 Excel 直接打开)。

## 6. 新增/改动模块(均在前端)

| 模块 | 类型 | 职责 |
|---|---|---|
| `HistoryStore` | 新增 namespace(仿 `FavoriteStore`) | 历史的加载/追加/裁剪/清空,`history.jsonl` 读写 |
| `HistoryPane` | 新增 `QDockWidget` | 历史面板 UI:搜索 + 列表 + 右键交互 |
| `Exporter` | 新增 | 把网格数据 → CSV/JSON/SQL 文件(流式写) |
| `GridEnhancer`(或并入 QueryForm) | 新增/改动 | 只读网格的筛选框、排序开关、复制、大值查看 |
| `BackendClient` | 改动 | SQL 执行出口加历史记录钩子(按 funcId 白名单) |
| `QueryForm` | 改动 | 挂筛选/排序/导出/复制;接 HistoryPane 的「送回 SQL」 |
| `OptionsDialog` | 改动 | 历史保留条数/天数配置项 |
| `MainWindow` | 改动 | 注册历史 dock、菜单项、快捷键 |

## 7. 测试策略

沿用项目现有 Qt 测试结构(`test.pro` 单元、`test_integration.pro` 集成,
离屏 `QT_QPA_PLATFORM=offscreen`):

- `HistoryStore`:追加、裁剪(超条数/超天数)、损坏行容错、加载排序,纯逻辑单测。
- `Exporter`:给定固定行列数据,断言 CSV(含 BOM、分隔符、转义)、JSON、INSERT
  输出字节,纯逻辑单测。
- 网格增强:筛选隐藏行数、排序后顺序、复制内容(TSV/CSV)断言。
- 历史记录钩子:对执行类 funcId 入账、对元数据类不入账(可在集成测试覆盖)。

## 8. 阶段二预告(不在本设计内)

数据导入:文件解析(CSV/Excel/SQL)→ 列映射 UI → 后端批量写入(事务、冲突处理)。
依赖对目标表结构的读取,后端需新增批量写入能力。届时单独出设计与计划。

## 9. 验收标准(阶段一)

- 执行任意写/查 SQL 后,历史面板能搜索到该条并能「送回编辑器」;重启后历史仍在;
  超限自动裁剪。
- 只读结果网格可点表头排序、可按关键字筛选(并明示仅作用当前数据)、可复制为
  TSV/CSV/JSON/INSERT、可双击查看大值。
- 可把结果(全部/选中/筛选后)导出为 CSV(中文在 Excel 正常)、JSON、SQL INSERT。
- 可编辑网格(TableDataForm)不受排序影响,编辑/主键定位行为不回归。
- 现有测试全绿,新增模块有对应单测。
